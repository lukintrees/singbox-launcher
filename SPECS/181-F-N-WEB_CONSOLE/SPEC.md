# SPEC 181 — LX Web Console: управление `sing-box lxd` и реестром нод из браузера

Статус: **N** (идея, не начата). Тип: **F** (Feature). Дата: 2026-11-12.
Платформа: все (сервер консоли — macOS/Windows/Linux там, где есть daemon-движок;
клиент — любой браузер).

Источник: запрос владельца 2026-11-12 — «адаптировать GUI в вебе, перенести
именно управление lxd-демоном и глубокую настройку: проработанные парсеры прокси
и т.д.».

---

## 0. Одна фраза

**Не портировать Fyne в браузер, а вынести из лаунчера «мозг» (парсер → реестр →
сборка конфига → управление демоном) за уже существующий HTTP-шов и надеть на него
отдельную веб-консоль**, которая работает и в браузере рядом с лаунчером, и
головой без GUI — на роутере, VPS, в докере, на телефоне оператора.

---

## 1. Проблема

Лаунчер сегодня — это **350 файлов Fyne** (`ui/`, ~78,5 тыс. строк), поверх которых
лежит очень крепкая, но запертая в десктопе начинка:

| Что | Где | Объём | Сколько знает про Fyne |
|---|---|---|---|
| Реестр контракта (20 схем, 120 кодов warning, корпус 2103 кейса) | `contract/` | 3,7 тыс. строк + данные | 0 |
| Движок разбора: маппер → санитайзер → эмиттер | `core/config/linkmap`, `nodeflow`, `registry` | ~36,7 тыс. строк | 0 |
| Состояние v8 + миграции + бэкап 1.0 | `core/state`, `core/backup` | ~11 тыс. строк | 0 |
| Сборка конфига из шаблона (`@var`, `#if`, пресеты, `for_each_node`) | `core/template`, `core/build` | ~7,4 тыс. строк | 0 |
| Модель формы узла по реестру (блоки, видимость, варианты, парсинг значений) | `ui/configurator/business` | ~10 тыс. строк | **0** (проверено) |
| Клиент демона (mTLS, admin REST, gRPC, wire-журнал, именованные команды) | `internal/lxdclient` | 1,5 тыс. строк | 0 |
| Реестр машин, пул транспортов, деплой, ресурсы | `core/services/lxd_remote_*` | ~6,9 тыс. строк | 1 файл из ~30 |
| Debug API с готовыми группами `/state/*`, `/remote/*`, `/daemon/*`, `/chains/*` | `core/debugapi` | 6,1 тыс. строк, **92 пути** | 0 |

То есть **начинка уже безголовая**. Головы к ней две неравноценные:

1. `ui/` — Fyne, живёт только за рабочим столом, требует OpenGL, на роутере и
   VPS невозможна, и любая новая ручка в Debug API до неё доезжает отдельной
   работой (двойная реализация одного и того же экрана).
2. `core/debugapi` — HTTP, но **только для агентов**: нет стримов (SSE сознательно
   отложен, см. `remote_observe_endpoints.go` §1), нет ни одного экрана, токен
   в заголовке, loopback-only, и группа `/state/*` покрывает серверы/правила/DNS,
   но **не трогает подписки, папки-nodes, directions, vars** — то есть
   конфигуратор целиком через неё не собрать.

Практические боли, которые это создаёт:

- **Настройка только с того Mac, где стоит лаунчер.** Роутер `RouteRich` и VPS
  настраиваются через SSH-туннель к десктопу или вообще не настраиваются.
- **Демон пережил лаунчер — а управлять им нечем.** `sing-box lxd` живёт в
  systemd/launchd/SCM и держит ядро, но Start/Stop/Apply без лаунчера — это
  `curl` с сертификатом в руках.
- **Телефон/планшет оператора — слепая зона.** LxBox умеет своё, но не умеет
  реестр машин десктопа.
- **Каждая фича пишется дважды.** Спеки 160/161/162 сначала делают core/Debug API,
  потом экран Fyne — и именно экран Fyne остаётся единственным местом, где
  «глубокая настройка» реально доступна.

## 2. Что именно переносим (и что нет)

Перенос — по признаку **«данные и правила, а не пиксели»**. Переносится то, что
уже безголовое; не переносится то, что является рабочим столом.

### Переносится (ядро идеи)

1. **Управление демоном `sing-box lxd`** — ровно то, что просил владелец:
   - паспорт (`GET /admin/info`: версия, `state_dir`, `executable`, `log_path`,
     `listen`, `tls`, платформа, init);
   - `status` / `start` / `stop` / `rollback` / `apply` (с откатом на last-good);
   - именованные команды оператора (`GET/POST /admin/commands/{name}`) — «sudo
     только в вашем терминале» сохраняется: консоль **показывает** команду, а не
     исполняет её (принцип SPEC 100 §2.4 / CONSTITUTION неизменен);
   - `clients-info`, метки клиентов LAN, `resources` (ресурс-стор машины);
   - наблюдаемость: группы/прокси/переключение/задержки/пул, правила ядра,
     соединения, DNS-запросы, лог ядра, телеметрия хоста, интерфейсы, режим
     Clash, цепочки (`/chains`, послойная проба).
2. **Глубокая настройка нод** — то, чем лаунчер силён:
   - форма узла **из реестра**, а не из кода: `Registry.FormFields` +
     `FormState` дают блоки (`connection`/`tls`/`transport`/`advanced`/`amnezia`),
     видимость по `visible_when`, обязательность с `required_unless`, активный
     вариант группы (`security: none|tls|reality`), `form.fixed`, `form.implies`,
     диапазоны, enum'ы, секреты. Всё это уже считается таблицами контракта.
   - разбор источников: ссылки, `base64`-списки, sing-box JSON, Xray-массив,
     `.conf` WG/AWG, `vpn://` — общий движок `linkmap` + корпус 2103 кейса;
   - предупреждения по коду реестра (120 кодов) с текстами **en/ru прямо из
     `warnings.json`** — веб не заводит своих строк и не расходится с LxBox;
   - эмиссия обратно в share-URI (`Emit`, round-trip уже закреплён корпусом).
3. **Реестр машин** (`core/services/lxd_remote_*`) — сопряжение по приглашению
   `адрес#отпечаток#код`, per-machine профиль, сборка конфига под платформу
   машины, деплой (ресурсы строго раньше конфига), здоровье, ресурсы, backup.

### Не переносится (сознательно)

- Трей, глобальные хоткеи, окна-диалоги ОС, запрос пароля/`sudo` из UI
  (привилегированные операции остаются строками-рецептами в терминале).
- Классический движок (спавн `sing-box run`) **как объект управления в вебе**:
  веб-консоль говорит с демоном, не с процессом. Classic остаётся десктопным.
  (Чтение его состояния через прокси-эндпоинт — см. §4.6.)
- Рендер Fyne-виджетов в WASM. Fyne/WASM существует, но это перенос пикселей,
  а не перенос логики, и на сервере без GPU — тупик.

## 3. Архитектура: три слоя и один шов

```
┌───────────────────────────────────────────────────────────────────────────┐
│ 3. КЛИЕНТ — LX Web Console (статика: HTML/CSS/JS без сборки)              │
│    вкладки Local · Remote · Nodes · Rules/DNS · Service · Logs · Backup    │
│    состояние в URL (?machine=router&tab=nodes&sel=vless-3) — ссылка другу  │
└──────────────────────────────▲────────────────────────────────────────────┘
                               │  HTTP/JSON + SSE   (bearer или cookie-сессия)
┌──────────────────────────────┴────────────────────────────────────────────┐
│ 2. ФАСАД — `lxweb` (Go, без Fyne, без build-тегов)                        │
│    /api/v1/*  : тонкий, типизированный, стабильный (в отличие от debug)    │
│    /events    : SSE-мультиплексор (status, proxies, log, conns, host)      │
│    /ui/*      : встроенная статика (go:embed)                             │
└───┬───────────────────────────────────────────────────────────────┬───────┘
    │ переиспользует как библиотеку (не переписывает)               │
┌───▼───────────────────────────────────────┐   ┌───────────────────▼───────┐
│ 1a. ГОЛОВА БЕЗ GUI — `core/headless`      │   │ 1b. ДЕМОН (вне процесса)  │
│  state.Load/Save · build.BuildConfig      │   │  sing-box lxd             │
│  linkmap разбор/эмиссия · registry формы  │   │  admin REST + gRPC        │
│  backup export/import · RemoteRegistry    │   │  mTLS, пин, приглашения   │
│  TransportPool · lxdclient                │   └───────────────────────────┘
└───────────────────────────────────────────┘
```

**Шов — не новый.** Он уже есть: `ControllerFacade` (debugapi) + `RemoteAPI` +
`DaemonFacade` + `lxdclient`. Идея в том, чтобы:

1. **вынести из `core` остатки Fyne**, которые мешают запуску без рабочего стола
   (`UIService`, `tray_menu`, `elevation`, `ui_watchdog`, `taildrop_*`,
   `services/api_service` с `fyne.Do`) — за интерфейс `Presenter` (см. §4.1);
2. **поднять фасад `lxweb`**, который говорит с теми же сервисами, что и Fyne-UI,
   и отдаёт браузеру **типизированные DTO**, а не «как получилось» из debug-API;
3. **сделать Debug API и веб-консоль двумя клиентами одного фасада** (debug
   остаётся для curl/агентов и backwards-compatible).

Ключевое следствие: **новый экран = новая ручка фасада + вкладка в статике**.
Экран Fyne перестаёт быть единственным местом, где доступна глубокая настройка.

## 4. Решения (спорные места названы заранее)

### 4.1 `Presenter` вместо `UIService` в `core`

Сейчас `core` знает Fyne в 18 файлах (152 упоминания `UIService`, 11 вызовов
`fyne.Do*`). Для `--web` без рабочего стола это блокер: `uiservice.NewUIService`
поднимает `app.New()` и GL.

- `core/headless` получает интерфейс `Presenter` (уведомить, показать окно,
  обновить трей, скопировать в буфер, спросить подтверждение) с двумя
  реализациями: `fynePresenter` (обёртка нынешнего `UIService`) и
  `webPresenter` (нотификации → SSE `toast`, подтверждения → запрос в UI).
- Правки точечные: `ac.UIService.X` → `ac.presenter.X`. Это большая, но
  **механическая** волна; она же чинит давнюю болезнь — «core тащит Fyne».
- Тесты: `Presenter` маленький и мокается — `core` впервые тестируется без GUI.

### 4.2 Один бинарь, флаг `--web`

```
singbox-launcher                 # как сейчас: Fyne
singbox-launcher --web           # Fyne + веб на 127.0.0.1:9264 (обе головы)
singbox-launcher --web-only      # без Fyne, только фасад (роутер/VPS/docker)
singbox-launcher --web-only --listen 0.0.0.0:9264 --tls-cert … --tls-key …
```

`--web-only` — это и есть «адаптация в веб» по существу: тот же бинарь, тот же
реестр, тот же движок; нет только окна. Ядро запускается/держится демоном —
классический спавн в `--web-only` запрещён (иначе процесс без супервизора).

`go build` получает тег `noweb` (для сборок, где статика не нужна) и
`headless` (без Fyne вообще) — Win7-сборка (`go.win7.mod`, go1.20) остаётся на
`headless` + classic, потому что демона там нет.

### 4.3 Безопасность: loopback по умолчанию, три режима

Веб-консоль — это **админ-плоскость к ядру и к ключам нод**. Поэтому:

| Режим | Слушает | Аутентификация | Для кого |
|---|---|---|---|
| `local` (дефолт) | `127.0.0.1:9264` | bearer-токен из `settings.json`, ввод один раз → HttpOnly-cookie-сессия | `--web` рядом с лаунчером |
| `lan` | `0.0.0.0:9264` | тот же токен + пароль оператора (argon2id), TLS обязателен | роутер в домашней сети |
| `public` | за реверс-прокси | доверие к `X-Forwarded-*` только из `trusted_proxies` (список CIDR), TLS терминируется снаружи | VPS |

Правила (закрепить в `docs/SECURITY_MODEL.md` §новый):

1. **Секреты не маскируются в `/api/v1/state/*`** (как в debug-API: loopback =
   trust boundary), но **маскируются в `?redact=1`** — для скриншотов и тикетов.
2. **CSRF:** cookie-сессия + `SameSite=Strict` + требование `X-LX-Web: 1` на
   все мутации; для bearer-режима CSRF не применим.
3. **Приглашения и сертификаты** (mTLS-ключи машин) **никогда не покидают
   сервер** в открытом виде: UI получает `fingerprint` и «paired/unpaired»,
   приватный ключ — нет.
4. **Права:** веб-консоль **не** исполняет привилегированных команд — только
   отдаёт готовые строки (дословно принцип SPEC 100 §2.4).
5. **Аудит:** каждый мутирующий вызов — строка в журнал с IP/сессией
   (расширение `debugapi/mutation_log.go`).
6. **Ограничение частоты** на `/auth/*` и на `/api/v1/*/deploy`.
7. **`--web-only` без `--listen` не поднимается на 0.0.0.0 никогда** — только
   явным флагом (никакой «удобной» автодетекции).

### 4.4 Стримы: SSE, а не WebSocket

Все живые экраны (статус ядра, список прокси с задержками, лог, соединения,
телеметрия хоста, DNS-запросы, прогресс деплоя) — **один SSE-канал
`/events?topics=status,proxies,log`**. Причины: односторонний поток — ровно то,
что нужно; EventSource переподключается сам; работает через любой реверс-прокси;
не нужен `gorilla/websocket` (сегодня в `go.mod` нет ни одной ws-библиотеки —
не тащим).

Прокси к gRPC-стримам демона (`SubscribeStatus`, `SubscribeGroups`,
`SubscribeLog`, `SubscribeConnections`, `SubscribeDNSQueries`,
`SubscribeTailscaleStatus`, `SubscribeServiceStatus`, … — 14 стримов) делает
фасад: одна подписка на топик, N браузеров, backpressure через drop-oldest и
`X-LX-Dropped-N` в комментарии SSE.

### 4.5 Что в фасаде, чего нет в Debug API (главный прирост)

Debug API покрывает серверы/правила/DNS (SPEC 160), но **не покрывает**:

| Не хватает | Нужно вебу | Откуда берётся (уже есть в коде) |
|---|---|---|
| подписки (CRUD, refresh, tag-политика, UA/HWID identity) | вкладка Nodes | `core/config/subscription`, `state.Source{Kind: subscription}` |
| папки как контейнеры + `replace`/`fold` | дерево нод | `Source.Kind: folder`, `FolderReplace` |
| chains (CRUD, hops, `SetChainPositionEnabled` / проба) | вкладка Nodes → Chain | `state` chains, `/chains`, `/chains/{tag}/probe` |
| directions (глобальные направления) | вкладка Rules → Directions | `state.Directions` |
| vars шаблона (типизированные: enum/dns_server/outbound с allowlist) | вкладка Settings | `template` + `registry/vars.json` |
| пресеты (вкл/выкл, порядок, `num`) | вкладка Rules | `state/rules` kind=preset |
| **форма узла по реестру** (схема → блоки/поля/варианты) | Add/Edit node | `registry.FormFields`, `FormState` |
| **парсинг на лету** «вставил текст → увидел ноды + warning'и» | Add nodes, Preview | `linkmap` + `registry/warnings.json` |
| **эмиссия URI** (share) | карточка ноды | `linkmap.Emit` |
| **сборка конфига в preview** (шаблон + vars + ноды → JSON + отчёт) | вкладка Build | `build.BuildConfig`, `config.BuildReport` |
| diagnostics snapshot, goroutines, wire-журнал машины | вкладка Logs | `debugapi/snapshot.go`, `lxdclient/wire_log.go` |

Это и есть «перенести глубокую настройку»: **таблицы реестра становятся UI
напрямую**, без промежуточного рукописного экрана. Добавили протокол в
`contract/registry` → он появился в веб-консоли (и в Fyne, и в LxBox) без
единой строки UI-кода, потому что подписи берутся из `desc_en/desc_ru`, а
видимость/обязательность — из `form.*`.

### 4.6 Классическое ядро — режим «read-only гость»

`--web` рядом с лаунчером на десктопе умеет показать состояние classic-ядра
(прокси, переключение, задержки — через `api.Clash*`), но **не** заявляет
управление жизненным циклом: Start/Stop остаются в Fyne. В `--web-only`
вкладка Local просто отсутствует. Так мы не тащим в веб привилегии и не
создаём второй супервизор процесса.

### 4.7 Технология клиента: без сборки

Одностраничная статика: нативный ES-модульный JS + HTML + CSS, `go:embed`.
**Ноль npm в CI**, ноль node-тулчейна в релизе (сейчас в репозитории нет ни
одного `package.json` — и это преимущество). Правила:

- Никакого фреймворка: компоненты — функции, возвращающие DOM; состояние —
  один стор с подпиской.
- Реестр-driven формы рисует один и тот же `field()`-рендерер для всех 20 схем.
- CSS — тёмная/светлая тема через `prefers-color-scheme`, минимум 44px на
  тач-цели (телефон = первый класс граждан, а не «тоже вроде работает»).
- Локализация — те же `en`/`ru`-строки, что и в `bin/locale` (см. §5, риск R4).

## 5. Риски и как их снимаем

| # | Риск | Снятие |
|---|---|---|
| R1 | `core` без Fyne — большая механическая волна, можно сломать десктоп | Шов `Presenter` с двумя реализациями; десктоп компилируется и работает **до** появления веб-экранов; волна закрывается зелёным CI по всем платформам |
| R2 | Две головы разъедутся по поведению | Единственный источник — фасад: Fyne-UI постепенно переводится на те же ручки (не наоборот); расхождение ловится тестом «фасад ↔ экран» |
| R3 | Безопасность: админ-плоскость в браузере | §4.3; дефолт loopback; TLS обязателен вне loopback; приглашения/ключи не покидают сервер; аудит мутаций |
| R4 | Строки UI: реестр даёт `desc_en/desc_ru`, но подписи полей формы живут в `ui/configurator/business/node_form_labels.go` (60+ путей, Fyne-пакет) | Вынести подписи в данные: `contract/registry/labels.json` (или секция `label` в реестре) + генератор; это **бамп контракта** и полезно LxBox — у них та же проблема |
| R5 | `go1.20`/Win7-совместимость общего кода | Веб-фасад и реестр — без `min/max`, `slices`, `http.PathValue`; `tools/win7guard` в CI; `--web-only` на Win7 не собирается (тег `headless`), classic-часть не трогается |
| R6 | Стримы на слабом роутере (RouteRich, arm64) | Один SSE-мультиплексор, drop-oldest, лимит буфера на топик, `?rate=` для логов; никаких per-connection горутин на браузер |
| R7 | Демон недоступен (сопряжение потеряно, версия старая) | Каждый экран деградирует по правилам SPEC 161/162: диагноз + рецепт в терминал, а не пустой экран |
| R8 | Соблазн «сделать красиво» вместо «сделать то же» | Источник истины — реестр и корпус: UI не считает ничего сам, что уже посчитано в `core` |

## 6. Критерии приёмки

1. **`--web-only` на VPS без GPU и без X11** поднимает фасад, отдаёт статику,
   показывает `GET /api/v1/daemon/status` и живые стримы; `go build` без Fyne в
   зависимостях бинаря (проверяется `go list -deps`).
2. **Управление демоном из браузера:** status/start/stop/rollback/apply,
   именованные команды (только показ + копирование), паспорт, clients-info,
   метки клиентов, ресурс-стор — паритет с экранами `ui/service_window.go`,
   `ui/connection_local_daemon.go`, `ui/machine_*.go`.
3. **Глубокая настройка ноды:** открыть ноду → форма собрана из реестра
   (блоки/видимость/варианты), сохранить → тело изменилось ровно в путях формы
   (проверяется корпусом `contract/corpus/node_edit`), share-URI эмитится и
   парсится обратно тем же движком.
4. **Парсер на лету:** вставить тело подписки (URI-список, base64, sing-box,
   Xray, `.conf`, `vpn://`) → ноды + предупреждения с текстами из
   `warnings.json` на языке интерфейса; расхождений с корпусом нет.
5. **Реестр машин:** сопряжение по приглашению, деплой (ресурсы → конфиг),
   здоровье, авто-деплой, бэкап-экспорт/импорт профиля — всё из браузера.
6. **Ссылка как состояние:** `?machine=…&tab=…&sel=…` открывается на том же месте.
7. **Десктоп не сломан:** `singbox-launcher` без флагов ведёт себя как прежде;
   все проверки CI зелёные (все платформы + Win7 + контракт).
8. **Безопасность:** вне loopback без TLS не стартует; приглашение и ключи
   машин не появляются ни в одном ответе `/api/v1/*`; мутации аудируются.

## 7. Не-цели

- Портируемость пикселей Fyne / Fyne-WASM.
- Замена LxBox на мобиле (веб-консоль дополняет, не заменяет).
- Правка `contract/registry` ради красоты UI (только общие бампы вроде R4).
- Управление classic-ядром как процессом (§4.6).
- Многопользовательская консоль с ролями: одна админ-плоскость, один оператор.
- Удалённый доступ к чужому демону без сопряжения: только mTLS-канал машины.

## 8. Этапы (детали — PLAN.md)

| Волна | Что | Результат, который можно показать |
|---|---|---|
| **W0** | `core/headless` + `Presenter`, флаг `--web-only`, статика-заглушка | бинарь без Fyne отдаёт «hello» на 127.0.0.1:9264 |

| **W3** | реестр-driven форма + разбор/эмиссия на лету (`/api/v1/registry`, `/parse`, `/emit`) | «глубокая настройка»: любая схема, любой вариант, любой warning |
| **W4** | `/api/v1/build/*` (preview конфига + отчёт), деплой на машину, бэкапы | полный цикл: собрал → проверил → задеплоил → увидел в `/chains` |
| **W5** | безопасность (`lan`/`public`, TLS, сессии, аудит), локализация, мобильная вёрстка | роутер в LAN и VPS за прокси |
